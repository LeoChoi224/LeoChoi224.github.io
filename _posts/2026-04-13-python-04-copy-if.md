지난 시간에 list, tuple, set, dict를 배우면서 **mutable / immutable**이라는 말이 나왔는데, 오늘은 그 말이 왜 중요한지 알게 됐다.

오전에는 "복사했는데 왜 원본이 같이 바뀌는가"를 다루는 대입과 복사, 그리고 VSCode 디버거 사용법을 배웠고, 오후에는 조건문 `if`와 참/거짓 판정, SCE(Short-Circuit Evaluation)를 배웠다.

## 변수는 상자가 아니라 화살표다
지금까지 변수를 값을 담는 상자처럼 생각했는데, 정확히는 **값이 있는 곳을 가리키는 화살표(이름표)**라고 한다.

```
a = 10
        a ──→ [ 10 ]
b = a
        a ──→ [ 10 ] ←── b     두 화살표가 같은 곳을 가리킨다
```

`id()`로 그 가리키는 곳의 번호를 확인할 수 있다.

```python
a = 10
b = a
print(id(a), id(b))  # 같은 번호
print(a is b)        # True
```

## 대입은 주소를 복사한다
숫자는 immutable이라 값을 바꾸면 **새 객체가 만들어진다.** 그래서 `b`에는 영향이 없다.

```python
a += 1
print(a, b)  # 11 10
```

그런데 list는 mutable이라서 상황이 달라진다.

```python
A = [1, 2, 3]
B = A
A[1] = 20    # 새로 만들지 않고 그 자리에서 고친다
print(A, B)  # [1, 20, 3] [1, 20, 3]  둘 다 바뀐다
```

`B = A`는 리스트를 복사한 것이 아니라 **같은 리스트를 가리키는 화살표를 하나 더 만든 것**이었다.

| | 값을 바꾸면 | 결과 |
|---|---|---|
| immutable (int, str, tuple) | 새 객체를 만든다 | 다른 변수에 영향 없음 |
| mutable (list, dict, set) | 그 자리에서 고친다 | 같은 객체를 보는 모두에게 영향 |

지난 시간에 표로만 봤던 mutable / immutable의 진짜 의미가 여기서 드러난 것 같다.

## is와 ==
- `==`: 값이 같은가 (동등성)
- `is`: 같은 객체인가 (동일성)

```python
a = [10, 20, 30]
b = [10, 20, 30]
print(a == b)  # True   값은 같다
print(a is b)  # False  따로 만든 다른 객체다
```

수업에서는 동명이인 비유를 들었다. 이름이 같다고 같은 사람은 아니다.

파이썬은 자주 쓰는 작은 정수나 짧은 문자열을 미리 만들어두고 재사용하기 때문에, 값 비교에 `is`를 쓰면 우연히 `True`가 나올 때가 있다. 그래서 **값 비교는 `==`, `is`는 `if x is None` 같은 경우에만** 쓴다고 정리했다.

## 얕은 복사
원본과 따로 놀게 하려면 복사를 해야 한다.

```python
import copy

x = [10, 20, 30]
y1 = x               # 대입: 복사가 아니다
y2 = x.copy()        # 방법 1
y2 = x[:]            # 방법 2 (슬라이싱)
y2 = list(x)         # 방법 3
y2 = copy.copy(x)    # 방법 4

x[1] = 200
print(x, y1, y2)     # y2 만 안 바뀐다
```

그런데 얕은 복사는 **한 겹만** 복사한다.

```python
x = [1, 2, ['A', 'B', 'C']]
y = x.copy()

x[0] = 'python'   # 바깥 원소 변경 → y 는 안 바뀐다
y[-1][-1] = 'F'   # 안쪽 리스트 변경 → x 도 바뀐다
print(x, y)
# ['python', 2, ['A', 'B', 'F']] [1, 2, ['A', 'B', 'F']]
```

바깥 리스트는 새로 만들어졌지만, 안에 들어 있는 `['A', 'B', 'C']`는 여전히 하나를 같이 가리키고 있기 때문이다.

## 깊은 복사
안쪽까지 완전히 떼어내려면 `copy.deepcopy()`를 쓴다.

```python
import copy
y = copy.deepcopy(x)  # 안쪽까지 전부 새로 만든다
```

참고로 수업 코드의 마지막 deepcopy 예제는 `copy.deepcopy(x)`의 결과를 변수에 담지 않아서 얕은 복사와 출력이 똑같이 나왔다. `y = copy.deepcopy(x)`로 고쳐서 돌려보면 차이가 확실히 보인다.

## 디버깅
`print()`로 값을 찍어보는 것 말고, 코드를 고치지 않고 **실행을 멈춰 세워서 들여다보는** 방법도 배웠다.

1. 멈추고 싶은 줄 왼쪽을 클릭해서 breakpoint(빨간 점)를 찍는다.
2. 실행(▶)이 아니라 디버그로 실행한다.
3. 멈추면 명령으로 한 줄씩 진행한다.

```
step over : 한 줄씩 실행
step into : 실행할 함수 안으로 들어가기
step out  : 실행 중인 함수가 끝날 때까지 진행
resume    : 다음 breakpoint 까지 진행
stop      : 디버깅 종료
```

`watch`에 `id(x)`, `id(y)`, `id(x[2])`, `id(y[2])`를 걸어두고 돌려보면, 얕은 복사에서 바깥은 번호가 다르고 안쪽은 같다는 것이 눈으로 보인다.

## 조건문 if
오후에는 조건문을 배웠다. 제어문은 "위에서 아래로"라는 기본 흐름을 바꾸는 장치이고, 갈라지는 **조건문**과 되돌아가는 **반복문** 두 종류가 있다.

```python
a = -10
if a > 0:
    print('양수입니다')
elif a == 0:
    print('0 입니다')
else:
    print('음수입니다')
```

들여쓰기로 묶인 문장 덩어리를 블록이라고 하고, 같은 블록은 들여쓰기 칸 수가 정확히 같아야 한다.

파이썬은 비교 연산자를 수학처럼 이어 쓸 수 있다.

```python
if 0 <= score and score <= 100:  # 다른 언어 방식
if 0 <= score <= 100:            # 파이썬 방식
```

## if 대신 dict 쓰기
값 하나에 결과가 하나씩 딱 대응되면 `if~elif`를 늘어놓는 대신 dict를 쓸 수 있다.

```python
day = 0
result = {0: "월요일", 1: "화요일", 2: "수요일"}[day]
```

분기가 많아질수록 if 사슬보다 훨씬 읽기 쉬울 것 같다.

## 삼항 연산자
```python
result = "짝수" if n % 2 == 0 else "홀수"
diff = (a - b) if a > b else (b - a)
```

`(참일 때 값) if (조건) else (거짓일 때 값)` 형태다. if 문이 아니라 **값을 만들어내는 식**이라서 대입 오른쪽에 바로 쓸 수 있다.

## 참 / 거짓 판정
조건식에는 bool뿐 아니라 아무 값이나 올 수 있다. 규칙은 **비어 있으면 거짓, 뭔가 있으면 참**이다.

| 타입 | 참 | 거짓 |
|---|---|---|
| 숫자 | 0이 아닌 수 | `0`, `0.0` |
| str | `"abc"`, `" "`(공백도 참) | `""` |
| list / tuple / dict | 원소가 있으면 | `[]`, `()`, `{}` |
| None | - | 무조건 거짓 |

```python
result = (0)    # 거짓: 그냥 int 0
result = (0,)   # 참: 원소 1개짜리 tuple
```

지난 시간에 배운 tuple의 콤마가 여기서 다시 나왔다.

이 성질 덕분에 `if len(my_list) > 0:` 대신 `if my_list:`라고 쓸 수 있다.

## SCE (Short-Circuit Evaluation)
오늘 가장 신기했던 부분이다. `and`와 `or`는 True/False를 돌려주는 것이 아니라, **결과가 정해지는 순간 멈추고 그때 본 값 자체를 돌려준다.**

```python
print(0 or 100)              # 100     0은 거짓 → 오른쪽
print('Hello' or 'Python')   # Hello   참 → 왼쪽에서 멈춤
print('Hello' and 'Python')  # Python  참 → 오른쪽까지 확인
print([] and 'Python')       # []      거짓 → 왼쪽에서 멈춤
```

`A or B`에서 A가 참이면 B를 볼 필요가 없고, `A and B`에서 A가 거짓이면 역시 B를 볼 필요가 없다. 그래서 short circuit이라고 부른다.

이걸 if 대신 쓸 수도 있다.

```python
n % 5 == 0 and print(n, '은 5의 배수입니다.')
```

그리고 "원본을 바꾸는 메소드는 `None`을 돌려준다"는 규칙과 합치면, 바꾼 원본을 그대로 돌려받는 관용구가 된다.

```python
a = {'name': '이브'}
result = a.update({'gender': 'male'}) or a
print(result)  # {'name': '이브', 'gender': 'male'}
```

`a.update()`가 `None`(거짓)을 돌려주니 `or` 오른쪽의 `a`가 결과가 된다. 처음 보면 낯설지만, 앞으로 reduce를 배울 때 계속 나온다고 해서 확실히 이해해두려고 한다.

## pass와 블록 스코프
블록을 비워두면 문법 에러가 나기 때문에, 나중에 채울 자리에는 `pass`나 `...`을 쓴다.

```python
if 40 in data:
    pass
else:
    print('없습니다.')
```

그리고 파이썬의 `if` 블록은 **새로운 스코프를 만들지 않는다.**

```python
if 'a' in "abc":
    zz = 'a' * 2

print(zz)  # if 블록 밖에서도 쓸 수 있다
```

Java나 JavaScript였다면 블록 밖에서 `zz`는 사라진다. 파이썬에서 새 스코프를 만드는 것은 `def`, `lambda`, `class` 세 가지뿐이라고 한다.

## 헷갈리기 쉬운 부분
- 리스트나 dict를 함수에 넘길 때도 `=`처럼 주소가 넘어간다. 함수 안에서 리스트를 고치면 밖의 원본이 바뀐다.
- 2차원 리스트를 `[:]`로 복사하면 안쪽 행이 공유된다.
- 탭과 공백을 섞어서 들여쓰기하면 눈에 안 보이는 에러가 난다. 공백 4칸으로 통일하는 게 좋다.
- `2.1 + 0.2 - 2.3`은 실수 오차 때문에 정확히 0이 아니라서 거짓이 아니다.

## 오늘 배운 내용 정리
오늘은 대입과 복사, 디버깅, 그리고 조건문을 배웠다.

```
대입(=): 값이 아니라 주소를 복사한다.
mutable: list, dict, set 은 그 자리에서 바뀌어서 같은 객체를 보는 모두가 영향을 받는다.
is vs ==: 같은 객체인가 / 값이 같은가. 값 비교에 is 는 쓰지 않는다.
얕은 복사: copy(), [:], list() → 한 겹만 복사한다.
깊은 복사: copy.deepcopy() → 안쪽까지 전부 분리한다.
디버깅: breakpoint 를 찍고 step over / into / out 으로 따라간다.
if / elif / else: 흐름을 갈라놓는다. 0 <= x <= 100 처럼 이어 쓸 수 있다.
삼항 연산자: 값1 if 조건 else 값2.
Truthy/Falsy: 비어 있으면 거짓.
SCE: and / or 는 판단에 쓰인 값 자체를 돌려준다.
```

"사본을 고쳤는데 원본이 바뀐다"는 문제는 직접 겪으면 원인을 찾기 어려울 것 같은데, 변수를 화살표로 생각하니 이해가 됐다.

SCE는 아직 손에 익지 않아서, `0 or 100`이 왜 `True`가 아니라 `100`인지 다시 설명해보면서 익숙해지려고 한다.
