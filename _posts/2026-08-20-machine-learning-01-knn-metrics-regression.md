오늘부터 머신러닝 수업이 시작됐다. 지난주 데이터 분석에서는 데이터를 읽고, 정리하고, 그려보고, 결론은 사람이 냈다. 머신러닝은 그 결론을 컴퓨터가 내리게 한다.

규칙을 사람이 적으면 이런 모양이 된다.

```python
if 길이 > 20 and 무게 > 200:
    return "도미"
```

그런데 생선 종류가 7가지이고 특성이 5개면 조건문이 감당이 안 된다. 머신러닝은 규칙을 적지 않고, 데이터와 정답을 잔뜩 주고 "규칙은 네가 찾아"라고 시킨다.

| 구분 | 전통적 프로그래밍 | 머신러닝 |
|---|---|---|
| 내가 주는 것 | 규칙 + 데이터 | 데이터 + 정답 |
| 나오는 것 | 답 | 규칙(모델) |

오늘은 도미와 빙어를 구분하는 첫 모델을 만들고, scikit-learn의 구조와 "잘 맞혔다"를 재는 지표를 배운 다음, 숫자를 맞히는 회귀까지 갔다.

## 도미와 빙어 - 첫 분류 문제
여러 종류(클래스) 중 하나를 구별하는 문제를 **분류(classification)**라고 하고, 그중 둘 중 하나를 고르면 **이진 분류**다. 오늘의 문제는 생선의 길이와 무게만으로 도미(Bream)와 빙어(Smelt)를 구분하는 이진 분류였다. 데이터는 캐글의 Fish Market 데이터셋으로 159마리, 7종이 들어 있고 그중 도미 35마리와 빙어 14마리를 썼다. 둘은 크기 차이가 극단적이라 눈으로도 구분돼서, 모델이 맞았는지 사람이 바로 알 수 있는 좋은 예제다.

### 특성과 타깃
길이와 무게처럼 데이터를 설명하는 성질이 **특성(feature)**이고, "도미냐 빙어냐"가 **정답(target)**이다. 정답은 글자가 아니라 숫자로 알려줘야 해서 도미는 1, 빙어는 0으로 만들었다.

```python
fish_target = [1] * 35 + [0] * 14   # 도미=1, 빙어=0
```

이름이 여러 개라 헷갈리는데 정리하면 이렇다.

| 부르는 이름들 | 무엇 | 코드에서 |
|---|---|---|
| 특성, feature, 입력(input), 독립변수, X | 아는 것 | `fish_data` |
| 정답, label, target, 종속변수, y | 맞혀야 할 것 | `fish_target` |

입력은 대문자 `X`, 정답은 소문자 `y`로 쓰는 경우가 많은데, 수학에서 행렬은 대문자, 벡터는 소문자로 쓰는 관습 때문이다. 입력은 2차원 표이고 정답은 1차원 줄이다. 이진 분류에서 1인 클래스를 **양성**, 0인 클래스를 **음성**이라고 하는데 좋고 나쁨이 아니라 "찾으려는 그것"이 양성이다. 암 진단이면 암이 양성, 스팸 필터면 스팸이 양성이고, 오늘은 도미를 찾으려 했으니 도미가 양성이다.

### 입력은 2차원 배열이다
scikit-learn에 넣는 입력은 특성들을 담은 2차원 배열이어야 한다. 엑셀 표처럼 한 줄이 생선 한 마리, 한 칸이 특성 하나다.

```python
fish_data = [[l, w] for l, w in zip(length, weight)]
# [[25.4, 242.0],
#  [26.3, 290.0],
#  ...]
```

이렇게 정해두면 특성이 2개든 10개든 열 개수만 달라지고 알고리즘 코드는 하나도 안 바뀐다. 이걸 feature vector라고 부르고, 대부분의 머신러닝 프레임워크가 같은 방식을 쓴다. 그래서 앞으로 만날 에러의 절반이 `ValueError: Expected 2D array, got 1D array instead`라고 한다. 한 마리를 예측할 때도 한 줄짜리 표로 넣어야 한다.

```python
kn.predict([[30, 600]])     # 대괄호 두 겹
kn.predict([30, 600])       # 에러
```

### KNN - 가까운 이웃의 다수결
KNN(k-최근접 이웃)은 새 데이터가 들어오면 모든 훈련 데이터와의 거리를 재고, 가까운 k개를 골라 그중 다수인 클래스로 답한다. 전학 온 학생이 어느 반인지 모를 때 가장 가까이 앉은 5명이 어느 반인지 보고 정하는 것과 같다.

```python
from sklearn.neighbors import KNeighborsClassifier

kn = KNeighborsClassifier()
kn.fit(fish_data, fish_target)
kn.score(fish_data, fish_target)   # 1.0
kn.predict([[30, 600]])            # array([1]) → 도미
```

| 메서드 | 하는 일 |
|---|---|
| `fit(입력, 정답)` | 학습(훈련, 적합) |
| `score(입력, 정답)` | 평가. 분류에서는 정확도(accuracy), 0.0~1.0 |
| `predict(입력)` | 예측. 정답이 필요 없다 |

scikit-learn의 모든 모델이 이 세 메서드를 가진다. 알고리즘이 바뀌어도 코드는 그대로다.

그런데 KNN은 사실 훈련이랄 게 없다. `fit()`에 넣은 데이터를 그대로 저장해뒀다가, 새 데이터가 오면 가까운 데이터를 찾아볼 뿐이다. 실제로 `kn._fit_X`를 찍어보면 넣어준 데이터가 그대로 들어 있다(밑줄로 시작하는 내부용 속성이라 공부할 때만 들여다본다). 그래서 데이터만 있으면 되지만, 데이터가 많으면 예측할 때마다 모든 데이터와 거리를 계산해야 해서 느리다. 학습은 0초, 예측은 느린 알고리즘이다.

이웃 수를 정하는 `n_neighbors`가 재미있었다.

```python
kn49 = KNeighborsClassifier(n_neighbors=49)
kn49.fit(fish_data, fish_target)
kn49.score(fish_data, fish_target)   # 0.7142857142857143
print(35 / 49)                       # 0.7142857142857143 ← 똑같다
```

이웃을 49마리 전부 보면 항상 도미 35 대 빙어 14라서 무조건 도미라고 답한다. 그러면 도미 35마리만 맞고 빙어는 다 틀려서 정확도가 35/49가 된다. k를 크게 하면 "주변"이라는 말이 의미를 잃는다. 이렇게 내가 정해주는 값을 **하이퍼파라미터**, 모델이 학습으로 찾아내는 값을 **모델 파라미터**라고 한다. k는 데이터가 정해주지 않아서 여러 값을 넣어보고 제일 좋은 걸 골라야 한다. 거리 재는 방법(`p=1` 맨해튼, `p=2` 유클리드가 기본)이나 사용할 CPU 코어 수(`n_jobs=-1`이면 전부)도 지정할 수 있다.

## 훈련 세트와 테스트 세트
위에서 정확도가 1.0이었지만 배운 걸 그대로 물어본 것이라 의미가 없다. 문제집 답안지로 공부하고 문제집을 다시 풀어 100점을 맞았다고 잘하는 학생이라고 할 수 없는 것과 같다. 진짜 실력은 처음 보는 문제로 확인해야 한다. 그래서 데이터를 학습용인 **훈련 세트**와, 학습에 절대 안 쓰고 평가에만 쓰는 **테스트 세트**로 나눈다.

처음에는 앞에서 35개, 뒤에서 14개로 그냥 잘랐다.

```python
train_input, train_target = fish_data[:35], fish_target[:35]
test_input, test_target = fish_data[35:], fish_target[35:]

kn.fit(train_input, train_target)
kn.score(test_input, test_target)   # 0.0
```

하나도 못 맞혔다. 데이터가 도미 35마리 다음에 빙어 14마리 순서로 정렬돼 있어서, 훈련 세트에는 도미만, 테스트 세트에는 빙어만 들어갔기 때문이다. 도미만 배운 모델에게 빙어를 보여주면 전부 도미라고 답한다. 이걸 **샘플링 편향**이라고 하고, 데이터가 날짜순이나 카테고리순으로 정렬돼 있는 경우가 흔해서 실무에서도 자주 일어난다. 해결책은 골고루 섞는 것이다.

```python
input_arr = np.array(fish_data)
target_arr = np.array(fish_target)

np.random.seed(42)
index = np.arange(49)
np.random.shuffle(index)          # 데이터가 아니라 인덱스를 섞는다

train_input = input_arr[index[:35]]
train_target = target_arr[index[:35]]
test_input = input_arr[index[35:]]
test_target = target_arr[index[35:]]
```

입력과 정답을 따로 섞으면 짝이 어긋나서 3번 생선의 데이터에 7번 생선의 정답이 붙어버린다. 인덱스를 한 번만 섞어서 양쪽에 똑같이 적용하면 짝이 유지된다. 섞은 뒤에는 산점도로 훈련 세트와 테스트 세트가 골고루 퍼져 있는지 눈으로 확인했다.

실무에서는 `train_test_split()`으로 섞고 나누기를 한 번에 한다.

```python
from sklearn.model_selection import train_test_split

train_input, test_input, train_target, test_target = train_test_split(
    fish_data, fish_target, stratify=fish_target, random_state=42)
```

기본은 훈련 75%, 테스트 25%다. 리턴 순서가 입력 두 개(train, test) → 정답 두 개(train, test)라는 걸 주의해야 한다. 순서를 착각하면 에러도 없이 이상한 결과가 나온다.

`stratify=`에 타깃을 넘기면 원본의 클래스 비율을 훈련과 테스트 양쪽에 똑같이 유지해준다. 섞기만 했을 때는 데이터가 적어서 테스트 세트의 도미 대 빙어 비율이 3.3:1로 원본(2.5:1)과 달랐다. 분류 문제, 특히 한쪽 클래스가 아주 적은 데이터에서는 거의 항상 쓴다. 안 쓰면 테스트 세트에 양성이 하나도 안 들어갈 수도 있다. 다만 회귀처럼 타깃이 연속된 숫자면 비율이라는 게 없어서 쓸 수 없다.

## 수상한 도미 한 마리 - 스케일 문제
오늘의 클라이맥스였다. 테스트 점수가 1.0인 모델에 길이 25cm, 무게 150g짜리 생선을 넣었더니 빙어라고 답했다. 산점도로 보면 누가 봐도 도미 쪽인데 말이다.

```python
kn.predict([[25, 150]])             # array([0]) ← 빙어?

distances, indexes = kn.kneighbors([[25, 150]])
print(train_input[indexes])
# [[ 25.4 242. ]    ← 도미
#  [ 15.   19.9]    ← 빙어
#  [ 14.3  19.7]    ← 빙어
#  [ 13.   12.2]    ← 빙어
#  [ 12.2  12.2]]   ← 빙어
```

가장 가까운 5마리 중 4마리가 빙어였다. 알고리즘은 정확히 제 할 일을 했다. 문제는 두 축의 범위다. 길이는 10~40인데 무게는 0~1000이라, 거리를 계산하면 이렇게 된다.

```
거리² = (길이 차이)² + (무게 차이)²
      = (25 - 25.4)² + (150 - 242)²
      =   0.16       +  8464
```

무게 항이 8,464이고 길이 항은 0.16이다. 길이는 계산에 거의 영향을 못 주고, 사실상 무게만 보고 판단하고 있었던 것이다. 지도에 가로는 미터, 세로는 킬로미터로 그려놓고 거리를 잰 셈이다. 그래프의 x축 범위를 무게와 같은 0~1000으로 늘리면 모든 점이 세로 한 줄에 뭉치는데, 모델이 보고 있던 세상이 그 모습이다.

특성들이 동등한 영향력을 갖도록 기준을 맞추는 일을 **데이터 전처리**, 그중 특성의 단위를 맞추는 작업을 **스케일링**이라고 한다. 오늘은 표준점수를 썼다. 각 값이 평균에서 표준편차 몇 개만큼 떨어져 있는지로 바꾸는 것이라, 단위가 사라지고 "평균보다 1.5칸 위" 같은 공통 언어가 된다.

```python
mean = np.mean(train_input, axis=0)   # 열(특성)마다 따로
std = np.std(train_input, axis=0)
train_scaled = (train_input - mean) / std
```

`axis=0`으로 길이와 무게의 평균을 따로 구했고, 뺄셈과 나눗셈은 브로드캐스팅으로 한 번에 됐다.

여기서 가장 중요한 규칙이 있다. **테스트 세트와 새 샘플도 반드시 훈련 세트의 평균과 표준편차로 변환해야 한다.**

```python
new = ([25, 150] - mean) / std
test_scaled = (test_input - mean) / std   # 같은 mean, std
```

테스트 세트의 평균으로 테스트를 변환하면 훈련 때와 다른 자로 재는 셈이라 좌표계가 어긋난다. 더 근본적으로는 테스트 세트가 "아직 못 본 미래 데이터"를 흉내 낸 것이라, 그 평균을 쓰는 건 미래를 미리 엿보는 것이다. 실제 서비스에서는 예측 요청이 한 건씩 들어오는데 그 한 건의 평균이란 게 있을 수 없다. 테스트 정보가 훈련에 새어 들어가는 이런 문제를 **데이터 누수**라고 한다.

```python
kn.fit(train_scaled, train_target)
kn.score(test_scaled, test_target)   # 1.0
kn.predict([new])                    # [1.] ← 도미
```

알고리즘도 데이터도 그대로인데 단위만 맞추자 제대로 맞혔다. 다만 모든 알고리즘이 거리 기반은 아니다. KNN이나 SVM처럼 거리를 계산하는 모델, 경사 하강법으로 학습하는 모델에는 스케일링이 필요하지만, 결정 트리 계열은 "이 값보다 큰가 작은가"만 보기 때문에 스케일과 무관하다.

정리하면 앞으로 어떤 문제를 풀든 이 순서다. 데이터 준비 → 훈련·테스트 세트 나누기(섞기) → 전처리(스케일링) → 모델 생성과 학습 → 평가 → 예측. 학습한 모델은 `joblib.dump(kn, 'kn.pkl')`로 파일에 저장하고 `joblib.load()`로 불러 쓴다. 그런데 모델만 저장하면 안 된다. 새 데이터를 변환할 `mean`과 `std`를 잃어버리면 저장한 모델이 쓸모없어진다. 그래서 실무에서는 스케일러와 모델을 `Pipeline`으로 묶어 통째로 저장한다.

```python
from sklearn.pipeline import make_pipeline
pipe = make_pipeline(StandardScaler(), KNeighborsClassifier())
pipe.fit(train_input, train_target)   # 스케일링 + 학습이 한 번에
joblib.dump(pipe, 'model.pkl')        # 둘 다 저장된다
```

## scikit-learn의 구조
세상에는 결정 트리, SVM, 랜덤 포레스트, 로지스틱 회귀 같은 알고리즘이 수십 가지 있는데, 라이브러리마다 사용법이 다르면 배우는 데만 몇 달이 걸린다. scikit-learn의 답은 "전부 같은 방식으로 쓰게 만들자"다.

```python
model = KNeighborsClassifier()     # 이 줄만 바꾸면
model = LogisticRegression()       # 나머지 코드는
model = RandomForestClassifier()   # 그대로다
model.fit(X_train, y_train)
model.score(X_test, y_test)
```

TV든 에어컨이든 전원 버튼이 항상 같은 자리에 있는 리모컨 같은 것이다. 자주 쓰는 모듈은 이렇다.

| 모듈 | 무엇 |
|---|---|
| `sklearn.datasets` | 연습용 데이터셋 |
| `sklearn.preprocessing` | 전처리 (스케일링, 인코딩) |
| `sklearn.model_selection` | 데이터 나누기, 교차 검증, 하이퍼파라미터 탐색 |
| `sklearn.metrics` | 성능 평가 지표 |
| `sklearn.pipeline` | 전처리와 모델을 하나로 묶기 |
| `sklearn.linear_model` | 선형회귀, 릿지, 라쏘, 로지스틱 회귀 |
| `sklearn.neighbors` / `tree` / `ensemble` / `svm` | 알고리즘 종류별 서랍 |

모델을 쓰는 순서는 클래스 고르기 → 하이퍼파라미터를 넣어 인스턴스 만들기 → 데이터를 특성 배열(X)과 타깃(y)으로 준비 → `fit()` → 새 데이터에 적용이다. 마지막 단계에서 갈림길이 있다.

| 구분 | 지도학습 모델 | 전처리 / 비지도 변환 |
|---|---|---|
| 학습 | `fit(X, y)` | `fit(X)` (y가 없다) |
| 사용 | `predict(X)` | `transform(X)` |

`predict`냐 `transform`이냐로 그 객체가 무슨 일을 하는지 알 수 있다. 그리고 `KNeighborsClassifier()`처럼 아무 인자 없이도 동작하게 기본값이 정해져 있어서 일단 돌려볼 수 있다. 다만 기본값이 최선이라는 보장은 없다.

연습용 데이터셋은 패키지에 포함된 `load_*()`(iris, diabetes 등), 인터넷에서 받아오는 `fetch_*()`(california_housing 등), 무작위로 만드는 `make_*()`가 있다. `load_diabetes()`를 열어보면 `data`, `target`, `feature_names`, `DESCR`이 딕셔너리처럼 들어 있다. target이 몇 가지 값만 반복하면 분류용, 제각각인 숫자면 회귀용이다. 나이가 `0.038` 같은 값으로 나와서 이상했는데, `DESCR`을 읽어보니 제작자가 미리 스케일링해둔 값이었다. 그리고 수업 자료 표에 있던 보스턴 집값 데이터(`load_boston`)는 집값 예측에 인종 구성 변수가 들어 있다는 윤리적 문제로 scikit-learn 1.2에서 삭제됐다. 옛 예제를 따라 하다 `ImportError`가 나면 버전 문제다.

### 스케일러 - fit은 자를 만들고, transform은 그 자로 잰다

| 방법 | 공식 | 결과 범위 |
|---|---|---|
| 표준화 (`StandardScaler`) | `(x - 평균) / 표준편차` | 평균 0, 표준편차 1 |
| 정규화 (`MinMaxScaler`) | `(x - 최솟값) / (최댓값 - 최솟값)` | 0 ~ 1 |

```python
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler()

scaler.fit(X_train)                    # 평균과 표준편차를 계산해서 기억 (자를 만든다)
X_train_scaled = scaler.transform(X_train)   # 그 자로 잰다
X_train_scaled = scaler.fit_transform(X_train)   # 두 단계를 한 번에
```

아까 손으로 계산한 `mean`, `std`가 `fit()`이고 `(train_input - mean) / std`가 `transform()`이다. 스케일러 객체가 평균과 표준편차를 기억해줘서 변수를 따로 관리할 필요가 없다. `fit()`은 자기 자신을 돌려줘서 `scaler.fit(X).transform(X)`처럼 이어 쓸 수도 있다.

수업 예제는 사용법을 보여주려고 iris 데이터 전체에 `fit_transform`을 했지만, 모델을 학습할 때는 절대 이렇게 하면 안 된다. 전체 데이터로 평균을 구하면 테스트 세트의 정보가 훈련에 섞여 들어가는 데이터 누수다.

```python
X_train, X_test, y_train, y_test = train_test_split(X, y)
X_train_scaled = scaler.fit_transform(X_train)   # 훈련 세트로만 fit
X_test_scaled = scaler.transform(X_test)         # 테스트는 transform만
```

`fit_transform`은 훈련에만, 테스트에는 `transform`만이다. Pipeline을 쓰면 이 규칙을 알아서 지켜준다.

## 정확도만 보면 속는다
분류 모델의 `score()`는 정확도이고, `accuracy_score(y_test, predict)`로도 같은 값을 구할 수 있다. 지표 함수는 거의 전부 (정답, 예측) 순서다.

그런데 정확도가 높다고 좋은 모델이 아니다. 1,000명 중 암 환자가 5명인 데이터에서 무조건 "정상"이라고 답하는 모델은 정확도가 99.5%인데 암 환자는 한 명도 못 찾는다. 아까 `n_neighbors=49`로 무조건 도미라고 답했는데 71.4%가 나온 것도 같은 이야기다. 그래서 다른 지표들이 필요하다.

### 오차 행렬

| 실제 \ 예측 | 예측 음성(0) | 예측 양성(1) |
|---|---|---|
| 실제 음성(0) | TN (맞음) | FP (거짓 경보) |
| 실제 양성(1) | FN (놓침) | TP (맞음) |

이름을 읽는 법을 알면 안 외워도 된다. 앞 글자(True/False)는 맞혔는지, 뒤 글자(Positive/Negative)는 모델이 뭐라고 했는지다. False Negative는 "음성이라고 했는데 틀렸다", 즉 실제로는 양성이다. `confusion_matrix(y_true=y_test, y_pred=predict)`는 `[[TN, FP], [FN, TP]]` 모양으로 나오고, `matshow`로 색을 칠하고 `text`로 숫자를 얹으면 어디서 많이 틀렸는지 한눈에 보인다.

### 정밀도와 재현율

```
정밀도(Precision) = TP / (FP + TP)   양성이라고 한 것 중 진짜는 몇 %인가 (헛다리를 안 짚었나)
재현율(Recall)    = TP / (FN + TP)   실제 양성 중 몇 %를 찾아냈나     (놓친 게 없나)
```

분모만 보면 구분된다. 어느 쪽이 중요한지는 업무가 정한다.

| 예 | 놓치면(FN) | 헛다리 짚으면(FP) | 더 중요한 것 |
|---|---|---|---|
| 암 진단, 금융 사기 적발 | 환자를 놓친다 | 재검사하면 된다 | 재현율 |
| 스팸 필터 | 스팸 한 통을 본다 | 중요한 메일이 사라진다 | 정밀도 |

둘 다 높이면 되지 않나 싶지만 그게 안 된다. 무조건 양성이라고 답하면 재현율은 100%가 되지만 정밀도가 바닥나고, 아주 확실한 것만 양성이라고 하면 반대가 된다. 이 관계를 트레이드오프라고 한다.

### F1 - 둘을 하나로

```
F1 = 2 × (precision × recall) / (precision + recall)
```

정밀도와 재현율의 조화평균이다. 산술평균과 다른 점은 한쪽이 낮으면 점수가 확 떨어진다는 것이다.

| 정밀도 | 재현율 | 산술평균 | F1 |
|---|---|---|---|
| 0.9 | 0.9 | 0.90 | 0.90 |
| 1.0 | 0.1 | 0.55 | 0.18 |

산술평균이면 0.55로 그럭저럭 보이는데 F1은 0.18이다. 둘 다 높아야만 높은 점수가 나오게 하려고 조화평균을 쓴다.

### ROC 곡선과 AUC
모델은 사실 0/1이 아니라 확률을 낸다. `model.predict_proba(X_test)`는 클래스마다 확률을 주고, `predict()`는 양성 확률이 0.5를 넘으면 1이라고 답하는 것뿐이다. 이 0.5가 **임계값(threshold)**이다. 임계값을 낮추면 양성이라고 하는 게 늘어서 재현율이 오르고 정밀도가 내리고, 높이면 반대가 된다.

ROC 곡선은 임계값을 0에서 1까지 움직이면서 FPR(실제 음성 중 양성이라고 잘못 말한 비율)이 변할 때 TPR(재현율)이 어떻게 변하는지 그린 것이다.

```python
from sklearn.metrics import roc_curve, roc_auc_score

pred_proba_class1 = model.predict_proba(X_test)[:, 1]
fprs, tprs, thresholds = roc_curve(y_test, pred_proba_class1)
plt.plot(fprs, tprs, label='ROC')
plt.plot([0, 1], [0, 1], '--k', label='Random')   # 대각선 = 찍기

roc_auc_score(y_test, pred_proba_class1)
```

대각선은 동전 던지기이고, 곡선이 왼쪽 위로 볼록할수록 좋은 모델이다. AUC는 그 곡선 아래 면적으로, 1.0이면 완벽하고 0.5면 찍는 것과 같다. AUC는 "양성 하나와 음성 하나를 무작위로 뽑았을 때 모델이 양성 쪽에 더 높은 확률을 줄 확률"로 읽을 수 있고, 정확도나 정밀도처럼 임계값 0.5를 가정하지 않고 모든 임계값을 종합하기 때문에 모델끼리 비교할 때 자주 쓴다. `RocCurveDisplay.from_estimator(model, X_test, y_test)` 한 줄로 그릴 수도 있다.

## 회귀 - 농어의 무게를 숫자로 맞히기
도미냐 빙어냐는 답이 둘 중 하나였다. 그런데 경제 성장률, 주가, 배달 도착 시간처럼 정해진 보기가 없는 숫자를 맞히는 질문이 더 많다. 이렇게 임의의 숫자를 예측하는 문제가 **회귀**다. 정답을 주고 배우게 하는 지도학습이라는 점은 같고 정답의 생김새만 다르다. 오늘의 문제는 농어(Perch) 56마리의 길이로 무게를 예측하는 것이었다.

| 구분 | 분류 | 회귀 |
|---|---|---|
| 타깃 | 0, 1, 2 같은 정해진 클래스 | 242.0, 390.5 같은 아무 숫자 |
| 점수 | 정확도 | R²(결정계수) |
| 모델 이름 | `...Classifier` | `...Regressor` |

"회귀(regression)"라는 이름은 19세기 통계학자 골턴이 키 큰 부모의 자식이 평균 쪽으로 되돌아가는(regress) 현상을 연구하면서 붙인 이름이 굳은 것이라 뜻으로는 잘 안 통한다. 지금은 "숫자를 예측하는 문제"라는 뜻으로만 쓴다.

특성이 길이 하나뿐이라 `train_test_split` 결과가 `(42,)`처럼 1차원이었다. scikit-learn은 2차원을 요구하니 세로로 세워줘야 한다.

```python
train_input = train_input.reshape(-1, 1)   # (42,) → (42, 1)
test_input = test_input.reshape(-1, 1)
```

`-1`은 "알아서 계산해"라는 뜻이다. `reshape(1, -1)`로 쓰면 샘플 1개에 특성 42개짜리 가로 줄이 돼버리는데 둘 다 에러 없이 돌아가서 주의해야 한다. 샘플이 행이라는 원칙을 기억하면 세로가 맞다.

### KNN 회귀, R², MAE
KNN 회귀는 이웃 k개를 찾는 데까지는 분류와 같고, 다수결 대신 이웃들의 타깃 평균을 답으로 낸다. 클래스 이름만 `KNeighborsRegressor`로 바뀌고 코드는 똑같다.

```python
from sklearn.neighbors import KNeighborsRegressor
knr = KNeighborsRegressor()
knr.fit(train_input, train_target)
knr.score(test_input, test_target)   # 0.992809406101064
```

회귀에서는 정확한 숫자를 맞힌다는 개념 자체가 성립하지 않는다. 실제 무게가 242.0g인데 241.7g이라고 했으면 맞은 걸까 틀린 걸까. 그래서 점수로 **R²(결정계수)**를 쓴다.

```
          (타깃 - 예측)²의 합
R² = 1 - ─────────────────────
          (타깃 - 평균)²의 합
```

분자는 내 모델의 오차, 분모는 그냥 평균으로 찍었을 때의 오차다. 그러니 R²는 "평균으로 찍는 것보다 얼마나 나은가"다. 1이면 완벽하고, 0이면 평균으로 찍는 것과 같고, 음수면 평균보다 못하다. 정확도와 달리 음수가 나올 수 있는데, 버그가 아니라 진짜로 나쁜 것이다.

R²는 얼마나 잘하는지는 알려주지만 얼마나 틀리는지는 안 알려준다. 그건 MAE(평균 절대 오차)로 본다.

```python
from sklearn.metrics import mean_absolute_error
mean_absolute_error(test_target, knr.predict(test_input))   # 19.157... → 평균 19g쯤 빗나간다
```

R² 0.9928이 좋은 건지는 감이 안 오지만 "19g 오차"는 바로 판단된다. 큰 오차에 더 민감하게 하고 싶으면 오차를 제곱해서 평균 내는 MSE나 거기에 제곱근을 씌운 RMSE를 쓴다.

### 과대적합과 과소적합

```python
knr.score(test_input, test_target)     # 0.9928
knr.score(train_input, train_target)   # 0.9699
```

테스트 점수가 훈련 점수보다 높았다. 풀어본 문제집을 다시 푸는데 처음 보는 시험보다 못 본 셈이라 이상한 일이다.

| 상태 | 훈련 점수 | 테스트 점수 | 비유 |
|---|---|---|---|
| 과대적합 (overfit) | 높음 | 낮음 | 문제집만 통째로 외웠다 |
| 과소적합 (underfit) | 낮음 | 낮음 또는 더 높음 | 공부를 덜 했다 |
| 적절 | 높음 | 조금 낮음 | |

그리고 머신러닝의 목표는 훈련 점수가 아니라 테스트(실제로 들어올 데이터)에서의 점수다. 지금은 과소적합이라 모델을 더 복잡하게 만들어야 했다. KNN에서는 k를 줄이면 복잡해진다. 헷갈리는 지점인데, k가 작으면 이웃을 조금만 봐서 주변에 예민한 복잡한 모델이 되고(과대적합 위험), k가 크면 많이 봐서 뭉뚱그리는 단순한 모델이 된다(과소적합 위험).

```python
knr.n_neighbors = 3
knr.fit(train_input, train_target)
knr.score(train_input, train_target)   # 0.9805
knr.score(test_input, test_target)     # 0.9746
```

훈련이 테스트보다 조금 높은 정상적인 모양이 됐다. `np.arange(5, 45).reshape(-1, 1)`처럼 입력 범위 전체를 촘촘히 만들어 예측시키고 선으로 이으면 모델이 학습한 함수 모양을 볼 수 있다. k=1이면 점 하나하나를 따라가서 들쭉날쭉하고(과대적합), k=10이면 세부를 뭉개는 뭉툭한 계단이 됐다(과소적합). KNN 회귀의 예측선은 이웃 조합이 바뀌는 순간에만 값이 바뀌어서 항상 계단 모양이다.

### KNN 회귀의 한계 - 50cm도 100cm도 1,033g

```python
knr = KNeighborsRegressor(n_neighbors=3)
knr.fit(train_input, train_target)
knr.predict([[50]])    # [1033.33333333]
knr.predict([[100]])   # [1033.33333333]
```

50cm 농어를 1,033g이라고 했는데 실제로는 훨씬 무겁다. 100cm짜리도 똑같이 1,033g이다. KNN에게 훈련 데이터 밖은 존재하지 않는 세상이라, 아무리 멀리 가도 가장 오른쪽 끝의 이웃 3마리가 계속 이웃이고 답이 그 평균에 고정된다. 데이터 사이를 예측하는 내삽은 잘하지만 데이터 밖을 예측하는 **외삽**은 못 한다. 결정 트리나 랜덤 포레스트도 같은 이유로 외삽을 못 한다. 해결하려면 더 큰 농어 데이터를 구해야 하는데 그게 여의치 않을 수 있다.

### 선형 회귀 - 직선을 학습한다
선형 회귀는 흩어진 점들 사이에 가장 잘 맞는 직선 하나를 긋는다. 모든 점에서 직선까지의 세로 거리를 제곱해서 더한 값이 가장 작아지는 직선을 찾는데, 이걸 최소제곱법이라고 한다.

```python
from sklearn.linear_model import LinearRegression
lr = LinearRegression()
lr.fit(train_input, train_target)
lr.predict([[50]])                # [1241.83860323]
print(lr.coef_, lr.intercept_)    # [39.01714496] -709.0186449535477
```

모델이 찾은 식은 `무게 = 39.02 × 길이 - 709.02`다. "길이가 1cm 늘면 무게가 약 39g 늘어난다"처럼 학습한 결과를 사람이 읽을 수 있다. `coef_`는 기울기(계수, 가중치), `intercept_`는 절편이고, scikit-learn은 `fit()` 이후에 생기는 학습 결과에 뒤 밑줄을 붙인다.

여기서 두 알고리즘의 본질적인 차이가 보였다.

| 구분 | 사례 기반 학습 (KNN) | 모델 기반 학습 (선형 회귀) |
|---|---|---|
| 학습이란 | 데이터 저장 | 최적의 모델 파라미터 찾기 |
| 저장하는 것 | 데이터 전부 | 숫자 두 개 (`coef_`, `intercept_`) |
| 예측 속도 | 느림 (매번 거리 계산) | 빠름 (곱셈 한 번) |
| 범위 밖 예측 | 못 한다 | 한다 |
| 설명 가능성 | 낮음 | 높음 |

농어 42마리를 배웠는데 저장할 게 숫자 두 개라는 게 놀라웠다. 그런데 선형 회귀에도 문제가 있었다.

```python
lr.score(train_input, train_target)   # 0.9398
lr.score(test_input, test_target)     # 0.8248
```

훈련과 테스트의 차이가 크고, KNN(k=3)보다 둘 다 낮아서 오히려 과소적합에 가까웠다. 그리고 결정적으로 무게가 음수로 나온다. `39.02 × 길이 - 709.02`라 길이가 18.2cm보다 짧으면 무게가 0보다 작아진다. 직선에는 "물고기 무게는 0보다 크다"는 상식이 없다. 모델이 너무 단순하다는 구체적인 증거다.

### 다항 회귀 - 곡선으로 늘리기
산점도를 다시 보면 점들이 직선이 아니라 위로 휘어진 곡선을 그린다. 2차 방정식 곡선을 학습하려면 길이를 제곱한 항을 입력에 추가하면 된다.

```python
train_poly = np.column_stack((train_input ** 2, train_input))   # (42, 2)
test_poly = np.column_stack((test_input ** 2, test_input))

lr = LinearRegression()
lr.fit(train_poly, train_target)      # 타깃은 그대로
lr.predict([[50 ** 2, 50]])           # [1573.98423528] 예측할 때도 제곱값을 같이
print(lr.coef_, lr.intercept_)        # [  1.01433211 -21.55792498] 116.0502107827827
```

모델을 바꾸지 않고 입력에 열을 하나 더 만들어준 것이다. 바꾼 건 입력(X)뿐이고 정답(y)은 그대로다. 예측할 때도 `[[50 ** 2, 50]]`처럼 제곱값을 같이 넣어야 하고, `[[50]]`만 넣으면 특성 개수가 안 맞아 에러가 난다. 모델이 찾은 식은 `무게 = 1.01 × 길이² - 21.56 × 길이 + 116.05`이고, 점수는 훈련 0.971, 테스트 0.978로 직선(0.940, 0.825)보다 훨씬 좋아졌다. 곡선은 점들의 흐름을 잘 따라가고 왼쪽 아래에서 음수로 내려가지도 않는다. 다만 테스트가 훈련보다 조금 높아서 여전히 과소적합 기미가 있다.

2차 방정식인데 왜 "선형" 회귀인지에 대한 설명이 좋았다. 길이² 대신 "왕길이"라고 이름을 붙이면 `무게 = 1.01 × 왕길이 - 21.56 × 길이 + 116.05`로, 무게가 왕길이와 길이의 선형 관계로 표현된다. 선형의 기준은 그래프가 직선이냐가 아니라 계수에 대해 1차식이냐다. 이렇게 다항식을 사용한 선형 회귀를 **다항 회귀**라고 한다. 길이²의 범위(100~1,900)가 길이(10~44)와 크게 다른데도 스케일링 없이 잘 동작한 건, `LinearRegression`이 경사 하강법이 아니라 수식으로 한 번에 푸는 방식이라 스케일에 영향을 덜 받기 때문이다.

마지막으로 데이터에는 길이 말고도 높이(Height)와 두께(Width)가 있었다. 무게는 길이 하나보다 여러 특성의 영향을 받을 테니, 내일은 특성을 여러 개 쓰는 다중 회귀로 넘어간다.

## 헷갈리기 쉬운 부분
- scikit-learn의 입력은 항상 2차원 배열이다. 한 건을 예측할 때도 `[[30, 600]]`이고, 특성이 하나면 `reshape(-1, 1)`로 세운다.
- 데이터를 나눌 때는 반드시 섞는다. 정렬된 데이터를 그냥 자르면 정확도가 0.0이 나올 수 있다. 분류면 `stratify`를 준다.
- `train_test_split`의 리턴 순서는 입력 두 개, 정답 두 개다.
- 스케일링은 훈련 세트의 평균과 표준편차로, 테스트와 새 샘플에도 똑같이 적용한다. `fit_transform`은 훈련에만, 테스트에는 `transform`만 쓴다.
- 모델을 저장할 때 스케일 정보도 같이 저장해야 한다. Pipeline으로 묶으면 편하다.
- 지표 함수의 인자는 (정답, 예측) 순서다. 순서를 바꾸면 정밀도와 재현율이 뒤바뀐다.
- 클래스가 셋 이상이면 `precision_score` 같은 지표에 `average=`를 정해줘야 한다.
- R²는 음수가 나올 수 있다. 평균으로 찍는 것보다 못하다는 뜻이다.
- 훈련 점수보다 테스트 점수가 높으면 과소적합이다. KNN은 k를 줄이면 복잡해진다.
- 다항 회귀는 예측할 때도 제곱항을 같이 넣어야 한다.

## 오늘 배운 내용 정리
오늘은 KNN으로 첫 분류 모델을 만들고, scikit-learn의 구조와 평가지표, 그리고 회귀를 배웠다.

```
머신러닝: 데이터 + 정답을 주면 모델이 규칙을 찾는다. 특성(X)은 2차원, 타깃(y)은 1차원.
API: fit(학습) → score(평가) → predict(예측). 전처리는 fit → transform.
나누기: train_test_split(X, y, stratify=y, random_state=42). 안 섞으면 샘플링 편향.
스케일링: 훈련 세트의 mean, std로 훈련·테스트·새 샘플을 똑같이. 안 그러면 데이터 누수.
KNN: 이웃 k개의 다수결(분류) / 평균(회귀). 데이터를 저장할 뿐이고 외삽을 못 한다.
평가: 정확도만 보면 속는다. 오차 행렬 → 정밀도(헛다리) / 재현율(놓침) → F1 → ROC-AUC.
회귀 점수: R²(평균 대비 얼마나 나은가, 음수 가능) + MAE(평균적으로 몇 g 틀리나).
과대적합: 훈련 >> 테스트. 과소적합: 훈련 < 테스트 또는 둘 다 낮음.
선형 회귀: coef_, intercept_ 두 숫자를 찾는다. 직선이라 음수 무게가 나온다.
다항 회귀: 입력에 제곱항을 추가. 계수에 대해 1차식이라 여전히 선형 회귀다.
```

정확도 100%인 모델이 25cm, 150g짜리 생선을 빙어라고 했던 이유가 "거리"와 "단위" 때문이었다는 게 가장 기억에 남았다. 알고리즘은 정확히 제 할 일을 했는데 단위가 달라서 무게만 보고 있었고, 스케일만 맞추자 바로 도미라고 답했다. 그리고 정확도 99.5%인데 암 환자를 한 명도 못 찾는 모델처럼, 점수 하나만 보고 좋은 모델이라고 믿으면 안 된다는 것도 같이 남았다.
