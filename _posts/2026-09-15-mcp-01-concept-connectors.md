오늘부터 MCP 단원이 시작됐다. 지난주까지 LangGraph로 에이전트에게 도구를 쥐여주는 법을 배웠는데, 그 도구들은 전부 내가 만든 프로그램 안에서만 쓸 수 있었다. 오늘은 AI가 바깥의 파일, 메일, 엑셀, 검색 같은 서비스와 대화하기 위한 공통 규격인 MCP가 무엇인지 개념부터 잡고, 클로드에 여러 서비스를 직접 연결해봤다. 코드는 거의 없고 연결 방식이 서비스마다 어떻게 다른지를 손으로 확인하는 날이었다.

## MCP가 필요했던 이유
챗GPT나 초기 클로드 같은 생성형 AI는 질문에 답을 만드는 건 잘했지만, 내 컴퓨터의 파일을 읽거나 구글 드라이브에 접근하거나 실시간으로 검색하는 것처럼 외부 데이터와 서비스에 직접 연동하는 일은 못 했다. 서비스마다 "이 AI를 이 서비스에 연결하는 코드"를 매번 따로 만들어야 했기 때문이다.

흔히 드는 비유가 USB-C 이전의 충전기다. 기기마다 충전 단자가 달라서 전용 케이블이 필요했던 걸 USB-C 하나로 통일한 것처럼, MCP는 AI와 외부 서비스를 잇는 단자를 하나로 통일한 것이다. 2024년 11월 클로드를 만든 앤트로픽이 이 표준을 오픈소스로 발표했고, 오픈소스라서 Notion, Tavily 같은 다른 회사도 자기 서비스용 MCP 서버를 만들어 배포할 수 있다. 오늘 여러 회사의 MCP를 한 클로드 안에서 섞어 쓸 수 있었던 이유가 이것이다.

> MCP는 AI 모델과 외부 데이터 소스 및 다양한 도구를 안전하고 표준화된 방식으로 연결해주는 개방형 프로토콜이다.

쉽게 말하면 AI와 외부 서비스가 "이렇게 대화하자"고 미리 정해둔 공통 언어다. 예전에는 AI와 구글드라이브, AI와 슬랙, AI와 엑셀을 연결할 때마다 다른 규격으로 연동 코드를 짜야 했는데, 서비스들이 MCP 규격만 따라 서버를 만들어두면 어떤 AI 호스트든 같은 방식으로 붙을 수 있다. 연동 코드를 서비스 개수만큼 짜는 게 아니라 표준 하나만 익히면 된다.

## MCP 아키텍처 - 호스트, 클라이언트, 서버

```text
사용자 → [MCP 호스트: 클로드 데스크탑 등]
              └─ [MCP 클라이언트] ──1:1── [MCP 서버] ── 로컬 파일 / 원격 API
```

사용자의 요청은 호스트, 클라이언트, 서버를 거쳐 처리되고, 필요하면 서버가 로컬 데이터나 원격 서비스에 접근한다.

| 구성 요소 | 역할 | 오늘 실습에서의 예 |
|---|---|---|
| 호스트(Host) | 사용자가 직접 쓰는 메인 프로그램. 여러 클라이언트·서버를 관리하고 전체 흐름과 보안을 담당 | 클로드 데스크탑, AI 기반 IDE |
| 클라이언트(Client) | 호스트 안에서 서버 하나마다 1:1로 붙어 데이터를 주고받는 중계 역할 | 클로드 데스크탑 안의 각 MCP 연결 |
| 서버(Server) | 실제 데이터 제공·도구 실행을 담당하는 경량 프로그램. 로컬/원격 어디서든 동작 | 엑셀 MCP, Tavily MCP, Gmail MCP |
| 로컬 데이터 소스 | 서버가 접근하는 내 컴퓨터의 파일·DB | 내 PC에 열려 있는 엑셀 파일 |
| 원격 서비스 | 서버가 연결해 가져오는 인터넷 너머의 API | Tavily 검색 API, Gmail 서버 |

헷갈렸던 건 클라이언트가 서버마다 따로 있다는 부분이었다. 엑셀, Tavily, Gmail 서버 세 개를 동시에 쓰면 호스트 안에도 클라이언트가 세 개 떠서 각각 1:1로 통신한다. 클라이언트 하나가 여러 서버를 몰아서 관리하는 구조가 아니다.

## MCP 서버의 3요소
MCP 서버가 LLM에게 컨텍스트를 제공해서 답의 질을 높이는 기능적 요소는 세 가지다.

| 요소 | 정의 | 쉬운 예 |
|---|---|---|
| 프롬프트(Prompt) | 언어 모델과의 상호작용을 유도하는 미리 정의된 템플릿·지시사항 | "이 메일에 정중한 답장 초안을 써줘" 같은 질문 틀 |
| 리소스(Resource) | 모델에 추가 컨텍스트를 주는 구조화된 데이터 | 받은 편지함 목록, 엑셀 시트의 현재 값 |
| 도구(Tool) | 모델이 작업을 수행하거나 정보를 검색하게 해주는 실행 가능한 함수 | 메일 보내기, 엑셀 셀 값 바꾸기 |

리소스와 도구는 "읽기냐 실행이냐"로 구분하면 된다. 리소스는 AI가 참고만 하는 데이터이고, 도구는 AI가 실제로 뭔가를 바꾸는 함수 호출이다. 오후 엑셀 실습의 `excel_get_values`(값 읽기)와 `excel_set_values`(값 쓰기)가 정확히 이 구분에 해당했다.

## 커넥터 연결 실습
MCP가 뭔지 알아도 실제로 내 클로드에 붙이는 절차를 모르면 그림의 떡이다. 오늘 실습에서 클로드는 전부 호스트였고, Desktop Commander, Firecrawl, Notion, Gmail, Google Drive, 엑셀, Tavily는 전부 서버였다. 결국 배운 건 이 서버들을 호스트에 등록하는 방법이 서비스마다 어떻게 다른가였다.

등록 방식은 크게 두 가지다. 원격 방식은 서버가 이미 그 회사 서버에서 돌고 있어서 클로드가 계정 인증(OAuth)만 하면 바로 연결되는 것으로, Notion, Gmail, Google Drive, Firecrawl이 이쪽이다. 로컬(stdio) 방식은 서버 프로그램을 내 컴퓨터에 설치하고 클로드가 그 실행 파일을 띄워서 표준입출력으로 대화하는 것으로, 엑셀 MCP가 이쪽이다. 내 PC의 엑셀 프로그램에 접근해야 하니 원격 서버로는 애초에 불가능하다.

### 내장 커넥터 - 클릭 몇 번으로 연결
클로드 설정 화면의 커넥터 목록에서 미리 만들어진 MCP 서버들을 켤 수 있다. 스마트폰에서 앱을 설치하지 않고 연동 허용만 누르는 것과 비슷하다. "연결하기"를 누르면 그 서비스 로그인 화면이나 API 키 입력 화면으로 넘어가고, 인증이 끝나면 도구 목록과 함께 등록된다.

- Firecrawl은 웹 스크래핑·크롤링 전용 MCP다. API Keys 화면에서 키를 발급해 연결하는데, 계정 하나에 워크스페이스가 여러 개 있을 수 있어서 정확한 워크스페이스를 골라야 한다. 로그인이 끝이 아니라 어느 방에 연결할지까지 확인해야 한다.
- Notion은 로그인 후 접근을 허용할 페이지를 직접 골라서 승인한다. 워크스페이스 전체가 아니라 내가 고른 페이지만 클로드가 보게 범위를 좁히는 방식이다.
- Gmail과 Google Drive는 계정 선택, 액세스 요청, 승인 순서로 구글 권한 화면이 뜬다. Gmail MCP는 메일을 읽기만 하는 게 아니라 보내는 도구까지 있어서 구글이 명시적으로 확인을 받는 것이다. 여러 구글 계정을 쓰고 있으면 의도한 계정을 골라야 한다.

수업에서는 다른 메일 계정으로 내 계정에 예제 메일을 보낸 뒤, 클로드가 Gmail MCP로 그 메일을 실제로 열람하고 처리하는지 확인했다.

### 로컬 설치형 - 엑셀 MCP
엑셀은 그 회사 서버에 로그인할 수 있는 서비스가 아니라 내 컴퓨터에서 실행 중인 프로그램 그 자체라서, 로컬 MCP 서버(pyhub-mcptools)를 직접 설치해야 한다.

```powershell
powershell -ExecutionPolicy Bypass -NoProfile -Command "iex (iwr -UseBasicParsing 'https://raw.githubusercontent.com/pyhub-kr/pyhub-mcptools/refs/heads/main/scripts/install.ps1')"
```

관리자 권한 파워셸에서 설치 스크립트를 돌리면 최신 버전을 내려받아 SHA256 체크섬으로 무결성을 검증하고 `C:\mcptools\`에 압축을 푼다. 체크섬은 파일 내용의 지문 같은 것으로, 다운로드 중에 손상되거나 변조되지 않았는지 확인하는 절차다. 처음 한 번은 `pyhub.mcptools.exe`를 더블클릭해서 윈도우 SmartScreen의 실행 차단을 "추가 정보 → 실행"으로 풀어야 했다. 프로그램이 잘못됐다는 게 아니라 출처가 불분명한 `.exe`를 처음 실행할 때 윈도우가 한 번 더 확인하는 것이다.

```bash
cd C:\mcptools\pyhub.mcptools
pyhub.mcptools.exe tools-list          # 서버가 제공하는 도구 목록
pyhub.mcptools.exe tools-list -v 3     # 각 도구의 인자까지 상세히

pyhub.mcptools.exe tools-call excel_get_opened_workbooks   # 열려 있는 엑셀 파일 목록
pyhub.mcptools.exe tools-call excel_get_values              # 활성 시트 전체 값 읽기
pyhub.mcptools.exe tools-call excel_get_values sheet_range="A3:C5"   # 특정 범위만
pyhub.mcptools.exe tools-call excel_set_values sheet_range="A8" values='val1,val2,val3\nval4,val5,val6'  # 값 쓰기
```

클로드에 연결하기 전인데도 `excel_get_charts`, `excel_add_chart` 같은 도구 목록이 나오고, 합계출산율 통계 엑셀 파일을 열어둔 채로 명령줄에서 값을 읽고 쓸 수 있었다. 로컬 MCP 서버가 명령줄에서 직접 호출해볼 수 있는 독립적인 프로그램이라는 걸 보여주는 부분이었다. 아직 GUI가 없어서 확인은 전부 명령 프롬프트에서 해야 한다.

```json
{
  "mcpServers": {
    "pyhub.mcptools": {
      "command": "C:\\mcptools\\pyhub.mcptools\\pyhub.mcptools.exe",
      "args": ["run", "stdio"]
    }
  }
}
```

마지막으로 클로드 데스크탑의 설정 → 개발자 → 구성 편집에서 `claude_desktop_config.json`에 이걸 추가하고, 클로드를 완전히 종료했다가 다시 켜야 반영된다. 윈도우 경로의 백슬래시를 두 번씩 쓰는 건 JSON에서 `\`가 이스케이프 문자라서 진짜 백슬래시 하나를 쓰려면 `\\`로 표시해야 하기 때문이다. 그리고 이 `command`와 `args`가 "호스트가 서버를 실행시킨다"는 말의 실체다. 클로드 데스크탑이 시작할 때 이 설정을 읽고 `pyhub.mcptools.exe run stdio`를 대신 실행해서 로컬 서버를 띄우고 표준입출력으로 대화를 시작한다.

### API 키형 - Tavily
Tavily는 LLM과 AI 에이전트 전용으로 설계된 실시간 웹 검색 API다. 구글 검색 결과를 AI가 바로 이해할 수 있는 형태로 정리해서 돌려준다. LangGraph 신문기사 챗봇에서 DuckDuckGo가 자꾸 막혀서 실무에서는 Tavily 같은 걸 쓴다고 했던 그것이다. 회원가입하면 API 키가 자동 발급되고, 대시보드에서 키를 복사해두면 된다. 무료 계정은 월 1,000회까지 호출할 수 있다.

이렇게 보니 연결 방식은 세 갈래였다. Gmail, Drive, Notion 같은 계정 로그인형, Tavily 같은 API 키형, 엑셀 같은 로컬 설치형이다. 새 MCP 서버를 만나면 이게 어느 쪽인지부터 가늠하면 된다.

## 헷갈리기 쉬운 부분
- MCP는 AI와 외부 서비스의 공통 연결 규격이다. 규격만 지키면 어떤 AI 호스트든 붙일 수 있다.
- 구조는 호스트 → 클라이언트 → 서버이고, 클라이언트는 서버 하나당 하나씩 1:1로 있다.
- MCP 서버는 프롬프트, 리소스, 도구로 이루어진다. 리소스는 AI가 읽는 데이터, 도구는 AI가 실행하는 함수다.
- 연결 방식은 계정 로그인형, API 키형, 로컬 설치형 세 갈래다.
- 내 PC에서 돌아가는 프로그램(엑셀)에 접근하려면 로컬 MCP 서버를 설치해야 한다.
- 계정이나 워크스페이스를 잘못 고르면 엉뚱한 데이터에 연결된다. Firecrawl, Gmail, Drive 공통 함정이다.
- `claude_desktop_config.json`의 `command`/`args`는 호스트가 로컬 서버를 실행하는 명령이다. 윈도우 경로는 `\\`로 쓰고, 고친 뒤에는 클로드를 완전히 재시작한다.

## 오늘 배운 내용 정리
오늘은 MCP의 개념과 구조를 배우고, 성격이 다른 서비스들을 클로드에 직접 연결해봤다.

```
MCP: AI ↔ 외부 데이터·도구를 잇는 개방형 표준 프로토콜. 2024.11 앤트로픽 오픈소스 발표.
구조: 호스트(클로드 데스크탑) → 클라이언트(서버마다 1:1) → 서버 → 로컬 데이터 / 원격 서비스.
서버 3요소: 프롬프트(질문 틀) / 리소스(읽는 데이터) / 도구(실행하는 함수).
연결 방식: 계정 로그인형(Notion, Gmail, Drive) / API 키형(Tavily, Firecrawl) / 로컬 설치형(엑셀 pyhub-mcptools).
로컬 등록: claude_desktop_config.json → mcpServers → command + args(run stdio) → 완전 재시작.
```

LangGraph에서 도구를 만들 때는 그 도구가 내 그래프 안에서만 쓰였는데, MCP는 그 도구를 프로그램 밖으로 꺼내서 어떤 AI든 같은 방식으로 쓰게 만드는 규격이라는 게 와닿았다. 실습에서는 같은 "연결하기"인데도 Notion은 페이지를 고르고, 구글은 계정을 고르고, 엑셀은 설치 파일과 JSON 설정까지 만져야 해서, 서비스가 어디서 돌아가느냐에 따라 연결 방식이 달라진다는 걸 직접 느꼈다. 내일부터는 이런 서버를 직접 만든다고 하니 기대된다.
